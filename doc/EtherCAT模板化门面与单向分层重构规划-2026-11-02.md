## 1. 目标形态

### 1.1 分层与所有权

```text
project/thread/test/trd_test.cpp            板卡、业务类型、策略的组装位置
  ecat::EthercatSlave<Rx, Tx>               模板门面：类型检查、业务编解码、外部生命周期
    EcatDevice                              生命周期与事件入口，不实现报文算法（非模板）
      AL 会话  →  EcatStateMachine          状态决策 + 有限转换步骤执行
      PDO 会话 →  EcatProcessData / EcatSync 缓冲、同步锁存、通道操作
      邮箱会话 →  EcatMailbox / EcatSdo / EcatSdoInfo
      对象访问 →  EcatDictionary            元数据查找、权限、线格式读写
      SII      →  EcatSiiService
      诊断     →  诊断叶子
  EcatEscHpm / PhyJl1111                    调用方拥有，寿命覆盖 Slave
```

### 1.2 核心约束（原文 §2.1 的落地版）

| 关系 | 规则 |
| --- | --- |
| 父对象 → 自己拥有的子对象 | 允许，直接调用并检查返回值 |
| 算法 → 描述表 / 字节视图 / 状态值 | 允许，借用止于本次调用 |
| 硬件操作 → `EcatEsc` | 允许，不接触具体 HPM SDK |
| SDO → Dictionary 实例 | **移除**，改成父层传入值与结果 |
| Sync → Dictionary 可写成员 | **移除**，同步参数由 Sync 自己拥有 |
| Mailbox → CoE 回调 → Device → SDO → Device → Mailbox | **移除**，改父层顺序调用 |
| StateMachine → 多个协议域 | **移除**，状态机只判断事实 |
| 下层 → Device 状态/时间戳回调 | **移除**，每次操作显式提供快照 |
| 服务指针集合 / 万能 Context / `friend` | **禁止** |

### 1.3 业务类型不进 core

模板只出现在两处：

1. `EthercatSlave<Rx, Tx>`（业务门面）
2. `SlaveProfile<Rx, Tx>`（Profile 生成器，编译期常量）

`EcatDevice` 及其以下全部是非模板类，通过非模板值类型 `DeviceProfile` 接收布局，只处理字节。

## 2. 模板门面设计

### 2.1 `interface/ecat_profile.hpp`（新建）

```cpp
namespace ecat {

/**
 * @brief 单方向的 PDO 布局契约
 * @tparam T 业务结构体
 */
template <typename T>
struct PdoProfile
{
	static_assert(std::is_trivially_copyable_v<T>, "PDO 类型必须可平凡复制");
	static_assert(sizeof(T) % sizeof(uint32_t) == 0, "PDO 必须按 32 位量对齐");
	static_assert(sizeof(T) <= kMaxProcessBytes, "PDO 超过单方向容量上限");

	static constexpr uint16_t kBytes = sizeof(T);					// 线上字节数
	static constexpr uint8_t  kWords = sizeof(T) / sizeof(uint32_t);	// 32 位字数
	static constexpr uint16_t kCaBytes = 2 + 4 * kWords;			// CA 长度：子索引 0 占 2 字节
};

/**
 * @brief 从站 Profile：两个方向由模板参数固定
 * @tparam Rx 主站→从站（SM2 / RxPDO）
 * @tparam Tx 从站→主站（SM3 / TxPDO）
 */
template <typename Rx, typename Tx>
struct SlaveProfile
{
	using Outputs = Rx;
	using Inputs  = Tx;

	static constexpr uint16_t kRxBytes = PdoProfile<Rx>::kBytes;
	static constexpr uint16_t kTxBytes = PdoProfile<Tx>::kBytes;
	static constexpr uint8_t  kRxWords = PdoProfile<Rx>::kWords;
	static constexpr uint8_t  kTxWords = PdoProfile<Tx>::kWords;
	static constexpr uint16_t kRxCaBytes = PdoProfile<Rx>::kCaBytes;
	static constexpr uint16_t kTxCaBytes = PdoProfile<Tx>::kCaBytes;

	// 整对象的 CA 上限（含子索引 0），供 SDO 缓冲定长
	static constexpr uint16_t kMaxCaBytes = (kRxCaBytes > kTxCaBytes) ? kRxCaBytes : kTxCaBytes;
};

/**
 * @brief 运行期传给 core 的布局值（非模板）
 */
struct DeviceProfile
{
	uint16_t rx_bytes = 0;	// 主站→从站字节数
	uint16_t tx_bytes = 0;	// 从站→主站字节数
	uint8_t  rx_words = 0;	// 主站→从站 32 位字数
	uint8_t  tx_words = 0;	// 从站→主站 32 位字数
};

}
```

**逻辑对应**：原文 §7.1「Profile 是唯一映射来源，同时生成 PDO 字节布局、0x1600/1A00、0x1C12/13、0x6000/7010 描述、分段容量上限」。本节把"唯一来源"固定在 `SlaveProfile`，其余全部从它派生。

**取舍说明**：当前只支持「等宽 32 位元素」的布局（与现实现一致）。混合字段宽度的描述表方案不在本次范围，留待 P7 之后单独立项；本规划不预先写不存在的机制。

### 2.2 `ethercat.hpp`（改模板）

```cpp
template <typename Rx, typename Tx>
class EthercatSlave final
{
public:
	using Profile = SlaveProfile<Rx, Tx>;

	EthercatSlave() = default;
	~EthercatSlave() = default;

	EthercatSlave(const EthercatSlave&) = delete;
	EthercatSlave& operator=(const EthercatSlave&) = delete;

	bool Init(EcatEsc& esc, EcatPhy* const* phys);	// 注入硬件，Init 内构建 Profile
	bool Poll();									// 推一拍，立刻返回
	void Disable();									// 停用协议栈

	bool    IsReady() const { return device_.IsReady(); }	// 初始化是否完成
	AlState State()   const { return device_.State(); }		// 当前 AL 状态

	const Rx& Outputs() const { return outputs_; }			// 最近一帧主站数据（ISR 写入）
	void SetInputs(const Tx& inputs) { inputs_ = inputs; }	// 线程侧写待发数据

private:
	static void OnOutput(void* context, const uint8_t* data, uint16_t length);	// ISR：MDI → outputs_
	static void FillInput(void* context, uint8_t* data, uint16_t length);		// ISR：inputs_ → MDI

	EcatDevice device_ {};		// 协议栈组合根
	Rx outputs_ {};				// 主站→从站业务镜像
	Tx inputs_ {};				// 从站→主站业务镜像
	EcatEsc* esc_ = nullptr;	// ESC 硬件
	EcatPhy* phys_[kPortCount] = {};	// 各端口 PHY，按真实端口下标
	uint8_t  phy_count_ = 0;			// 实际挂接的 PHY 数
	int64_t  next_link_poll_ = 0;		// 下次链路刷新时刻（ms）
};
```

**逻辑对应**：
- `OnOutput` 承接原文 §7.2 `SetOutputSink` 的业务边界责任，但改为**先 `memcpy` 到 `outputs_`**，业务侧通过 `Outputs()` 读强类型值，不再把 ESC 字节指针强转业务结构体（原文 §7.1 明确禁止）。
- `FillInput` 同理，从 `inputs_` `memcpy` 出去。
- `phys_[kPortCount]` 按**真实端口下标**存储（原文 D2 修正点），`phy_count_` 只用于统计。

### 2.3 ISR 与线程的数据可见性

`outputs_` 在 PDI ISR 写、线程读；`inputs_` 线程写、ISR 读。**本规划不新增锁**，与现状一致（32 位对齐的结构体读写本身不撕裂）。原文 §5 要求"事件上下文变更另行验证"，这里保持不变更，只把数据形态从裸指针换成值成员。
