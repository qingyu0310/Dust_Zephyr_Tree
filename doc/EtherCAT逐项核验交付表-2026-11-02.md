### 10.2 状态转换实测

```
[inf] ecat: al_control=0x11 req=0x01     ← 主站请求 INIT（带 ACK）
[inf] ecat: al_control=0x11 req=0x01
[inf] ecat: al_control=0x12 req=0x02
[inf] ecat: al_state -> 0x02             ← INIT → PREOP，邮箱起来
[inf] ecat: al_control=0x04 req=0x04
[inf] ecat: al_state -> 0x04             ← PREOP → SAFEOP，PDO/SM/同步校验通过
[inf] ecat: al_control=0x08 req=0x08
[inf] ecat: al_state -> 0x08 (first outputs)  ← 首帧到达，SAFEOP → OP
```

对照本表：

| 表项 | 实测证据 |
| --- | --- |
| `EnterPreOp`（EEPROM CRC/LOAD 检查 + `Mailbox::Start`） | `al_state -> 0x02`，失败路径未触发 |
| `EnterSafeOp`（PrepareSm→StartSm→SM2/3→区域校验→掩码） | `al_state -> 0x04`，全流程无错误码 |
| `EnterOp` + `CompletePendingOp` | 日志出现 `(first outputs)`，证明走的是"`EnterOp` 返回 `kAlStatusInWork` → SM2 首帧 → `CompletePendingOp` 补完"这条路径 |
| `Publish`（0x0134/0x0130/LED） | 主站能读回状态，转换被主站接受 |
| `HandlePdiEvents` SM2/SM3 | 计数同步增长（见下） |

### 10.3 稳态数据

```
[inf] ecat diag: state=0x08 code=0x0000 output=1 event=0x0000
[inf] ecat diag: pdi=8158 sm2=8157 sm3=8157
[inf] ecat diag: last_sm2_age_ms=1 max_gap_ms=2
```

| 指标 | 值 | 判读 |
| --- | --- | --- |
| `state` | `0x08` = OP | 稳定在 OP |
| `code` | `0x0000` | 无 AL 错误码 |
| `output` | `1` | 输出通道已开 |
| `event` | `0x0000` | AL 事件无堆积，全部已确认 |
| `pdi` : `sm2` : `sm3` | 8158 : 8157 : 8157 | 每个 PDI 一拍一个 SM2/SM3；差 1 是最后一个 SM2 的输入尚未被主站读走 |
| `last_sm2_age_ms` | 0~1 | 距最近一次 SM2 不超过 1 ms |
| `max_gap_ms` | 2 | 最坏情况差 1 个 tick，抖动可接受 |

### 10.4 断链与恢复实测

拔插网线两次，走完了「断链 → 看门狗退态 → 主站重连 → 全状态重建」的完整闭环。

```
[inf] ecat: al_control=0x08 req=0x08
[inf] ecat: al_state -> 0x08 (first outputs)       ← 进 OP
[wrn] ecat local state: 0x08 -> 0x04 code=0x001b   ← 看门狗超时，退到 SAFEOP
[err] ecat fault saved: id=1 t=149990 code=0x001b
[err] ecat rx stopped: state=0x04 code=0x001b output=0 event=0x0000
[err] ecat rx stalled: age_ms=840 pdi=111820 sm2=111840 sm3=111840
[inf] ecat: al_control=0x11 req=0x01 ×3            ← 主站拉回 INIT
[inf] ecat: al_state -> 0x02 → 0x04 → 0x08         ← 重建 PREOP→SAFEOP→OP
[inf] ecat rx resumed: state=0x08 sm2=112330       ← 恢复提示一条
```

| 观察项 | 实测 | 判读 |
| --- | --- | --- |
| 错误码 | `0x001B` | 是 `kSmWatchdog`（SM 看门狗），不是 `0x001A`（同步错误）→ 判定走的是过程看门狗分支 |
| 退态目标 | `0x08 → 0x04` | OP 退 SAFEOP，正确（`RequestLocalState` 的门控） |
| `output` | `0` | 退态后输出已关（`LeaveOp`） |
| `event` | `0x0000` | 残留事件已确认，无堆积 |
| `age_ms` | 840 / 344 | 两次断链时长不同，符合随机拔插 |
| 恢复 | `rx resumed` 一条 | 恢复检测生效，不刷屏 |
| 主站行为 | 自动重发 `0x11 req=0x01` | 主站侧也识别到退态并主动重新初始化 |
| 首次故障 | `fault saved: id=1` | 首次断链冻结现场，第二次只累加 `additional_faults_`，不覆盖 |

**这条实测覆盖了 §10.5 里原列的两项**：看门狗退态、主站恢复。

**一处待查**：第一次断链 `age_ms=840`，比常见的看门狗时长（通常几十到几百 ms）长。可能原因是主站停发后 `kPdWdTriggerMask` 需要满足时间才置位，而不是软件检测慢——`Poll` 是 1 ms 周期。用 `ecat fault` 能拉出 `wd: divider=X time=Y timeout_ms=Z` 那行核对主站配置的实际超时，当前未做。
