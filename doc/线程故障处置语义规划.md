# 线程故障处置语义规划

> 2026-10-23。基于用户当日明确给出的两条标准：**影响小的自杀，影响大的所有线程都杀了**。
> 本规划把 `framework/init/thread/` 的故障处置链路按这两条标准收拢，每一步都写死到文件与行。

---

## 1 现状与问题

| # | 问题 | 证据 | 后果 |
|---|------|------|------|
| 1 | `ThreadFaultPolicy::Recover` 的处理是 `Halt()`，但 `Halt()` 只是长鸣 + `k_msleep(1000)` 自旋 | `thread_fault.cpp:20-29` | **只卡死出故障的这一个线程，其他线程照常跑**，与「影响大的所有线程都杀了」完全不符 |
| 2 | `Thread::ExitThread()` 叫「退出」，内部却只有 ExitHook + 注销 + 打日志，**不终止线程** | `thread.hpp:388-397` | 真正让线程死的是 `Run()` 里那句 `return`；`ExitThread()` 名不副实，退出语义被拆成两处 |

## 2 目标语义（用户定案）

| 策略 | 影响面 | 处置 | 系统后续 |
|------|--------|------|----------|
| `Isolate` | 小（心跳、测试） | **自杀**：该线程执行 ExitHook → 注销注册表 → 终止自己 | 其他线程照常运行 |
| `Recover` | 大（姿态、遥控） | **全杀**：长鸣 → 所有线程逐个走 ExitHook + 注销 + 终止 | 系统静止，保留现场；`KeepAlive` 线程（shell）存活 |

**判定入口只有一个**：`Task` 返回 `Retry`，且 `RetryHook` 返回 `false`（或没装钩子）。
`RetryHook` 返回 `true` 表示线程自己扛住了，处置层不介入。

## 3 设计定案

### 3.1 删掉 `ThreadFaultAction`

默认处置函数不再「返回动作」，而是**直接执行动作**。

```cpp
// 整个枚举删除，不留任何残留
```

`DefaultHandle` 的返回类型由 `ThreadFaultAction` 改为 `void`。

### 3.2 `ThreadBase` 增加 `Exit()`

「终止」成为线程对象自身的能力，任何上下文都能调（自己调 = 自杀，别人调 = 处决）。

```cpp
/**
 * @brief 终止线程：挂起 → 执行 ExitHook → 注销注册表 → 打日志 → k_thread_abort
 *
 * 任意上下文可调：自己调即自杀（不返回），其他线程调即处决目标线程。
 */
virtual void Exit() = 0;
```

### 3.3 `Thread::Exit()` 实现

替换现有私有的 `ExitThread()`，**末尾必须真正终止线程**，不再依赖 `Run()` 里的 `return`。

```cpp
void Exit() override
{
    if (k_current_get() != &thread_) {
        k_thread_suspend(&thread_);     // 他杀：先冻住，亡语期间不会运行
    }

    if (fault_.exit_hook != nullptr) {
        fault_.exit_hook(task_.context);
    }

    (void)thread_registry::Remove(this);

    DUST_LOG_WRN("thread %s exited", Name());

    k_thread_abort(&thread_);
}
```

要点：
- **他杀必须先挂起目标**：否则亡语执行的几步里，目标线程可能被唤醒继续跑 `Task`，甚至重复进入 `Exit()`。`k_current_get() != &thread_` 用来区分自杀与他杀——自杀时不能对自己 `k_thread_suspend`。
- 不用 `irq_lock` 临界区：`ExitHook` 是业务写的任意代码，临界区内不能阻塞（`k_msleep` / `k_mutex_lock` / 带超时的 `zbus_chan_pub` 都是非法用法），约定不了。
- `k_thread_abort(&thread_)` 在**当前线程**执行时由内核切换到别的线程，本函数不再返回；在**其他线程**执行时把目标置 dead 后返回。
- 保留 `ExitHook`（用户要求三套生命周期分开：`RollbackFunc` / `RetryHook` / `ExitHook`）。
- 方法放在 `public`（`ThreadBase` 的纯虚实现必须可见）。

### 3.4 `Run()` 不再判断返回值

```cpp
if (result == TaskResult::Retry)
{
    atomic_inc(&stats_.retry_count);

    // 一级：Retry 钩子就地处理（钩子自己决定要不要节流打日志）
    if (fault_.retry_hook == nullptr || !fault_.retry_hook(task_.context))
    {
        // 二级：钩子处理不了 → 默认处置函数直接决定生死（不返回）
        DefaultHandle(this);
    }
}
```

`Run()` 里**不再有 `ExitThread(); return;`**，`Run()` 本身也没有任何退出点。

### 3.5 `DefaultHandle` 改 `void`

```cpp
void DefaultHandle(ThreadBase* thread)
{
    if (thread == nullptr) {
        Halt();
    }

    switch (thread->FaultPolicy())
    {
        case ThreadFaultPolicy::Isolate:
            DUST_LOG_WRN("thread %s fault, isolating", thread->Name());
            thread->Exit();     // 自杀：收尾后自己终止
            return;

        case ThreadFaultPolicy::Recover:
        default:
            DUST_LOG_ERR("thread %s fatal, halting", thread->Name());
            Halt();             // 全杀：不返回
    }
}
```

### 3.6 `Halt()` 杀光所有线程（保留标记除外）

```cpp
/**
 * @brief 停机：长鸣后终止所有线程，带保留标记的线程（shell）留作观察窗口
 */
[[noreturn]] static void Halt()
{
    EXEC_BUZZER_LONG();

    const k_tid_t self = k_current_get();

    // 先处决其他线程；Exit() 会把目标移出注册表，count 变小时同一位置由尾部补上。
    // 带保留标记的线程（shell 日志消费者）跳过不杀，留作停机后的观察窗口。
    for (uint8_t i = 0; i < thread_registry::Count(); )
    {
        ThreadBase* thread = thread_registry::At(i);
        if (thread == nullptr || thread->Tid() == self || thread->KeepAlive()) {
            ++i;
            continue;
        }
        thread->Exit();
    }

    // 最后处决自己（不返回）
    for (uint8_t i = 0; i < thread_registry::Count(); ++i)
    {
        ThreadBase* thread = thread_registry::At(i);
        if (thread != nullptr && thread->Tid() == self) {
            thread->Exit();
        }
    }

    // 调用者不在注册表（如中断上下文）时的兜底
    for (;;) {
        k_msleep(1000);
    }
}
```

要点：
- **顺序是自己最后**，否则 `Exit()` 自己会立刻切走，其他线程杀不掉。
- **`KeepAlive` 的线程跳过不杀**：shell 是日志消费者，杀了它收尾日志就发不出去，也失去停机后的观察窗口。
- 需要 `#include "thread_registry.hpp"`。
- 每个被杀线程都走 `ExitHook` + 注销 + 日志，不是裸 `k_thread_abort`。
- ⚠️ **被处决线程的 `ExitHook` 在调用者上下文执行**，不是在被杀线程自己的栈上——所以 `ExitHook` 里不能依赖本线程的局部状态，只能操作 `context` 里的成员。这是 `k_thread_abort` 本身的能力边界（内核不会给目标线程一个"去收尾"的执行机会），不是本设计的选择。
- 想让被处决线程的亡语在自己栈上跑，只能改成"标志位 + 目标自己检查"，但目标可能阻塞在 `k_sem_take` 永远醒不来，全杀会卡死——所以不采用。
