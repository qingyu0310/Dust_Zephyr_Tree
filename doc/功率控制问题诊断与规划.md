# 功率控制问题诊断与规划

> 日期：2026-08-05
> 数据：`低速透传.csv`（1954 行）、`vofa+1.csv`（817 行）、`80/120w非钳制输出.csv`
> 状态：**诊断完成 → 修复规划（待执行）**
> 一句话：**预测模型没问题（透传 1.35W 零偏差）；问题在功率控制（Allocate 限幅）——限幅生效但压不住实际功率，拆出两个问题：预测欠导致边缘漏限 + 限幅后 P_meas 仍超（4 电机分配待确认）。**

---

## 1. 已确认事实（证据落地）

### 1.1 预测准（透传段铁证）

`低速透传.csv`（1954 行，P_meas max 53W，超 60 = 0 行，完全透传）：

| 段 | n | \|err\|均 | err 均 |
|----|----|---------|--------|
| 透传全段 | 1083 | **1.35W** | **−0.04W（零偏差）** |
| P 5-15W | 214 | 1.46 | −1.04 |
| P 15-25W | 338 | 1.39 | −0.60 |
| P 25-35W | 429 | 1.15 | +0.48 |
| P 35-45W | 100 | 1.76 | +1.72 |

> **结论：预测模型没问题。** 透传（不限幅）下预测几乎精确。

### 1.2 限幅生效但压不住（60W 预算）

`vofa+1.csv`（817 行，打印 P_meas / 预测钳制 / pre电流 / late电流）：

| 指标 | 数据 |
|------|------|
| P_meas 超 60 | **363 行（44.4%）**，max 85W |
| 预测钳到 60 段（324 行） | P_meas 中值 **66.4**、95% 超 60、max 85 |
| 限幅生效率 | **96%**（late<pre，电流确实被压） |
| 最长连续超预算 | **0.5s**（9 行 @50ms） |

**核心矛盾**：限幅把电流压下来了（96% 生效），但实测功率仍 66-85W。

### 1.3 高功率档行为对照（80/120W）

| 预算 | 稳定 P_meas | 行为 |
|------|------------|------|
| 60W | 贴 60 但实测 66-85（压不住） | ❌ 问题 |
| 80W | 83.7（贴预算，实测超 4W） | ⚠️ 预测欠 |
| 120W | 101（透传，需求<预算） | ✅ 正常 |

## 2. 拆出的两个问题

### 问题 1：预测欠 → 边缘段漏限

`vofa+1.csv` 行 543：`P_meas=64.8, P_pred=59.9, pre=late=7.96（没限幅）`

- 预测 59.9W（差 0.1W 没到预算）→ **没触发限幅**，但实测 64.8W 超了
- 预测欠 **4-5W** → 限幅到"预测=60"时实测已 64-66W
- 80W 文件实测 83.7 > 预算 80 同源（+3.7W）

> 本质：**限幅用预测判断，预测欠 → 限幅点偏**。边缘段（预测 55-60）漏限。

### 问题 2：限幅压电流但 P_meas 仍 85W（持续 0.5s）

`vofa+1.csv` 行 541-547：`pre=5~9.7, late=3.4~6.3（持续限幅）`，P_meas 持续 65-85

- 行 545：电机0 电流从 9.49 压到 **4.26A**，但 P_meas=84.2
- 连续 7 行，**非 1-2 周期延迟**
- **pre/late 只取电机0**（`trd_chassis.cpp:155/178` `g_wh_current[0]`）→ 另外 3 电机是否限住未确认

## 3. 候选根因（代码级）

| # | 根因 | 证据/代码 | 对应问题 |
|---|------|-----------|---------|
| 1 | **开环预测限幅，无功率反馈**：限幅只看预测>60 就限电流，限完不核对实测 | `power_ctrl.hpp Allocate()`：`totalPred <= budget` 直通，否则限 | 问题 1 |
| 2 | **PID 结构性缺限幅（已确认，问题 2 最可能根因）**：`pid.hpp` Config 有 `outMax`/`iOutMax` 但 `trd_chassis.cpp` 未设（默认 0=无限）→ PID 输出冲到 14.55A、积分无限累积反推 → 60↔84 抖动 | `pid.hpp:56-57` 字段未用 + `trd_chassis.cpp` `speed_cfg` 只设 kp/ki/kd | 问题 2 |
| 3 | **反馈延迟**：预测用电机 CAN 反馈 τ/ω，滞后于限幅命令 | `Predict()` 用 `SetMotorData` 的实测 τ/ω | 问题 2（部分） |
| 4 | **membership 分配不均**：`powerLimit[i]=membership[i]·60`，分配不均则某电机分到过大限不住 | `Allocate()` membership 逻辑 | 问题 2 |

## 4. 下一步规划

### Step 1 诊断：确认问题 2 根因（4 电机电流）

改打印为 4 电机电流，重测 60W，确认"某电机没限住"还是"限幅目标本身不对"。

`trd_chassis.cpp` log_timer 打印（old→new）：

```cpp
// old（当前）
			printk("%f,%f,%f,%f\n", (double)PwrMeter.GetPower(), (double)ChassisPwrCtrl.GetTotalPowerClamped(), (double)pre_current, (double)late_current);

// new
			printk("%f,%f,%f,%f,%f,%f,%f,%f\n",
			       (double)PwrMeter.GetPower(), (double)ChassisPwrCtrl.GetTotalPowerClamped(),
			       (double)g_wh_current[0], (double)g_wh_current[1],
			       (double)g_wh_current[2], (double)g_wh_current[3],
			       (double)pre_current, (double)late_current);
```

**判定**：
- 限幅段 P_meas 高时，若 **4 电机电流都被压到很小** 仍超 → 限幅目标不对（预测欠/解方程 bug）→ 走 Step 3（余量）
- 若 **个别电机电流很大**（其他被限）→ membership/PID 反推 → 先走 Step 2（PID 限幅）

### Step 2 修 PID 限幅（问题 2 最可能根因，改动最小，先做）

`pid.hpp` Config 已有 `outMax`（输出限幅）/`iOutMax`（积分限幅），`trd_chassis.cpp` 未设置（默认 0=无限）。补上：

```cpp
// old（trd_chassis.cpp PID 初始化）
        alg::pid::Pid::Config speed_cfg {};
        speed_cfg.kp  = 10.0f;
        speed_cfg.ki  = 1.0f;
        speed_cfg.kd  = 0.0f;

// new：输出/积分硬限幅（一刀切保险，PID 输出永不超过预算对应电流）
        alg::pid::Pid::Config speed_cfg {};
        speed_cfg.kp      = 10.0f;
        speed_cfg.ki      = 1.0f;
        speed_cfg.kd      = 0.0f;
        speed_cfg.outMax  = 5.0f;    // 输出硬限幅（60W/4电机≈5A/电机，防 PID 冲 14A；可调）
        speed_cfg.iOutMax = 2.0f;    // 积分限幅（防限幅时积分无限累积反推；可调）
```

> `outMax=5A` = M3508 半额定（10A 额定），即使 Allocate 漏限，PID 也推不到 14.55A；`iOutMax` 封积分项，限幅时不再累积反推。具体值跑起来调。

### Step 3 修预测余量（问题 1，简单）

限幅目标降 5W 留余量，抵消预测欠的 4-5W。

`power_ctrl.hpp` Allocate()（old→new，给限幅判断加余量）：

```cpp
// old
    float totalPred = GetTotalPower();
    if (totalPred <= totalBudget) {
        // 未超限：透传
        ...
        return;
    }

// new：预算打 92% 余量（60→55.2），抵消预测欠
    constexpr float kBudgetMargin = 0.92f;          // 预测欠 4-5W，限幅目标降 8%
    float limitBudget = totalBudget * kBudgetMargin;
    float totalPred = GetTotalPower();
    if (totalPred <= limitBudget) {
        ...
        return;
    }
    // 限幅目标也用 limitBudget（否则余量无效）
    // 逐电机 powerLimit 用 limitBudget 算
```

> 注意：余量会让"需求 55-60W"的段提前限幅、速度略降——可接受（优先不超预算）。若实测余量过大（限制过狠），调 `kBudgetMargin` 到 0.95。

### Step 4 可选：功率反馈闭环（治本）

用实测功率 P_meas 反馈修正限幅（不只靠预测）：
- 限幅判断融合 `max(P_pred, P_meas)`，或
- 功率环（PID 对功率误差）动态调预算

> 治本但工作量大，先做 Step 1-3 验证是否够。
