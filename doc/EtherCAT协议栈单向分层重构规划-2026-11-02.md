# EtherCAT 协议栈单向分层重构规划

日期：2026-11-02。范围：从站协议栈、业务门面及其与 ESC、PHY 的组装边界。本文件只规划，不修改协议实现。

## 1. 基线和结论

本次基于当前工作区源码，而不是以旧 SSC 文件名为目标重新分文件。参考 `framework/drivers/communication/stream/usb/core/usb_dev_port.cpp` 的父对象拥有子对象、向下调用、明确处理结果的方式；EtherCAT 的状态转换、邮箱重发和时钟语义仍按自身协议处理。

当前 `core` 已拆成 AL、PDO、字典、邮箱等域，但对象所有权与调用方向没有一起拆开。最集中的证据是 `core/ecat_device.cpp:235` 的 `Init()`：

1. Sync 借用 Dictionary 的两个可写同步参数结构。
2. StateMachine 同时保存 Mailbox、ProcessData、Sync、SII、Dictionary 的引用。
3. Dictionary 回调 Device 查询状态、时间戳。
4. SDO、Info 保存 Dictionary，再经 Device 的 `SubmitReply()` 回到 Mailbox。
5. CoE 保存两个服务，Mailbox 又保存经 Device 返回 CoE 的分发回调。

这构成“父对象拥有所有子对象，子对象之间仍互相注册”的关系网。把这些 `Bind()` 换成构造参数，或者包进一个全局 Context，均不满足此次要求。

**目标：父对象单向驱动自己拥有的子对象；子对象只接收本次操作所需的数据并返回结果，不保存兄弟对象、不调用上层、不通过回调绕回兄弟对象。**

当前工程有多个脏子仓库，根仓库提交号不能代表完整源码基线。开始实施时必须分别记录 `framework/drivers`、`project` 等实际仓库的提交和未提交补丁；本规划不承诺已有改动已提交，也不执行回退。

路径约定：下文 `core/` 均相对于 `framework/drivers/communication/ethercat/`；行号为本次阅读的定位辅助，以函数名和具体条件为迁移依据。

## 2. 所有权和层次

```text
project/thread/...                           板卡、业务类型、策略的组装位置
  EthercatSlave<Rx, Tx, Profile>              类型检查、业务编解码、外部生命周期
    EcatDevice                               生命周期和事件入口，不实现报文算法
      AL 会话                                状态决策 + 有限转换步骤执行
        EcatStateMachine                     当前态、目标态、错误、pending、超时
      PDO 会话                               过程数据缓冲、同步锁存和通道操作
        EcatProcessData / EcatSync            各自拥有缓冲和同步运行状态
      邮箱会话                               帧所有权、服务选择、应答提交
        EcatMailbox                          SM0/SM1 传输、池、队列、重复发送
        EcatSdo / EcatSdoInfo                 各自拥有传输会话，不拥有发送通道
      对象访问                               元数据查找、权限、线格式读写
      EcatSiiService                         EEPROM 命令解释、延迟持久化状态
      诊断记录                               观察快照、冻结首次故障、按需回放
  ESC 实例 / PHY 实例                       调用方拥有，寿命覆盖 Slave
```

图中“AL 会话、PDO 会话、邮箱会话、对象访问、诊断记录”是目标责任边界，尚非已存在的类名。实施时在现有子树风格下确定命名，不能把图中的名称当成已有 API。

共同叶子是协议值类型、只读描述表、wire 编解码和 ESC 通道操作。允许上层组合根向下调用这些叶子；不要求为了层数给每个简单函数再套一层虚接口。

### 2.1 允许和禁止的依赖

| 关系 | 规则 |
| --- | --- |
| 父对象 → 自己拥有的子对象 | 允许，直接调用并检查返回值 |
| 算法 → 描述表、字节视图、状态值、配置值 | 允许；借用范围止于本次调用，除非明确声明为整个会话稳定的只读 Profile |
| 硬件操作 → `EcatEsc` | 允许，是向下的硬件能力边界；不接触具体 HPM SDK |
| SDO → Dictionary 实例、Sync → Dictionary 成员 | 移除，不保存兄弟实例或其可写字段地址 |
| Mailbox → CoE 回调 → Device → SDO → Device → Mailbox | 移除，改成父对象顺序调用及返回结果 |
| StateMachine → 多个协议域 | 移除；状态机只判断事实，转换执行者调用各域 |
| 下层 → Device 状态/时间戳查询回调 | 移除，每次对象访问显式提供值快照 |
| 服务指针集合、万能 Context、`friend` 访问兄弟私有成员 | 禁止，不能借包装恢复原依赖图 |
| ESC HAL 回调、业务接收/供数回调 | 属于外部事件边界，可以保留；不是内部对象互相初始化的手段 |

共享配置必须有唯一权威持有者。同步参数由同步域持有；字典只是提供它的协议投影，不再拥有一份与 Sync 可相互修改的运行数据。AL 状态只归状态机，时间戳只归同步域，帧分配/释放只归邮箱传输。

## 3. 初始化和销毁

目标初始化只接受硬件、只读 Profile、业务适配配置，不接受 Mailbox、Dictionary、Sync 等兄弟对象参数。

| 顺序 | 操作 | 失败处理 / 依据 |
| --- | --- | --- |
| 1 | trd 声明 ESC、按真实端口排列的 PHY、Rx/Tx 类型、Profile、回调 | 声明寿命必须覆盖事件和会话 |
| 2 | 校验 Profile：映射位数、SM 上限、SDO 会话容量、业务编码长度 | 不开硬件；不提交一半布局 |
| 3 | 构造所有内部域的独立状态；安装业务边界 | 无兄弟 Bind；不开放 IRQ |
| 4 | `esc.Open()` 注册硬件回调，硬件事件保持关闭 | 失败返回，清除借用状态 |
| 5 | 读 CommInfo 的实际 SM 数，禁用所有通道；清 AL 事件掩码并发布 INIT；初始化 SII 读宽度 | 对应当前 Device Init，不使用固定 4 通道代替实际通道数 |
| 6 | 初始化各实际 PHY 端口；配置、MDIO 地址由 trd 明确提供 | 失败逆序清理已经开启的资源，不留下可运行 Device |
| 7 | 发布可运行标志，再 `StartEvents()` | 解决当前 StartEvents 早于 ready、PHY、业务回调完成的窗口；这是显式生命周期调整 |
| 8 | 正常 Poll；按原端口下标轮询链路 | 空端口不能压缩编号 |

销毁先阻止新事件并等在途入口退出，再终止邮箱/SDO/Info、停止同步、清 PDO、发布 INIT、处理待持久化 SII，最后关闭硬件。复位保留“清全部协议会话后重新启用事件”的语义，不能只 StopEvents 后仍保留 ready。

初始化改造与事件执行上下文改造分开提交。中断开启前后的内存可见性、重入以及 StopEvents 是否等待在途回调，必须由硬件契约定义，不能只靠 `bool ready_` 解决。

## 4. 状态机拆分：保留协议顺序，移走兄弟依赖

状态机输入为 AL Control、当前会话事实、执行结果、时间推进。输出为有限的下一步骤和最终状态，而非保存所有服务的执行接口。

执行步骤采用同步、固定类型的结果，不建异步命令总线，不用堆分配。执行者仅在状态边界做编排，不复制各域算法，也不把整个协议重新塞回 Device。

### 4.1 转换顺序和失败分支对照

| 当前源码 | 目标归属 | 必须保留的逻辑 |
| --- | --- | --- |
| `al/ecat_state_machine.cpp` `HandleControl()` | 状态决策 | 分离请求态、ACK、Device ID；处理未知目标、BOOT；新请求取消旧 pending；有错误且未 ACK 的请求门控；InWork 不写作 AL 错误码 |
| `Transition()` 前置分支 | 状态决策 | 同态请求；SAFEOP/OP ACK 时通道恢复；非法跳转；INIT→OP 不允许；不能用统一成功分支吞掉这些条件 |
| `Transition()` 映射及 SM 检查 | AL 转换执行 | 当前目标 SAFEOP 时先 Configure 再 CheckSmSettings；PREOP 检查 2 个通道，其余检查 4 个；失败不进入后续启动 |
| `EnterPreOp()` | AL 转换执行 → 邮箱会话 | EEPROM CRC/装载检查；Mailbox Start 失败立即 Stop |
| `EnterSafeOp()` | AL 转换执行 → PDO 会话 | PrepareSm→StartSm→清缓冲/首帧标志→启用有效 SM→读取并保存地址→验证区域→预提交输入→设置掩码→input_running |
| `EnterSafeOp()` 失败分支 | 同上 | StartSm 失败 Stop；区域失败禁用 SM2/3 并 Stop；不能只返回错误让已启动硬件悬空 |
| `EnterOp()` / `MarkFirstOutputs()` | 状态决策 + PDO 执行 | 有 RxPDO 必须等首个输出；InWork、pending 目标、当前态的门控；无 RxPDO 独立处理；先完成允许输出条件再开放业务回调 |
| `LeaveOp()` | 状态决策 | 停止业务输出并清首帧；不因重新收到 PDO 自动清 AL 错误或进入 OP |
| `LeaveSafeOp()` | AL 转换执行 | 停 SM2/3、清过程数据与同步事件掩码、StopSm、清用户同步选择、停止输入 |
| `LeavePreOp()` / `BackToInit()` | AL 转换执行 | 关闭邮箱、同步收尾；BOOT 不支持的返回保持显式 |
| `Transition()` 失败状态归位 | 状态决策 + 执行回滚 | 按目标态分支处理，不能统一 Reset；原代码资源清理不一致项见第 10 节，单独修复 |
| `Tick()` / `CheckTimeout()` | 状态决策 | Tick 只推进时间；各目标等待时限、到期收尾、首帧超时码及发布顺序逐项保留 |
| `CheckSmSettings()` | 独立 SM 配置校验 + 通道确认 | 邮箱启用、长度、方向、单缓冲、地址范围；SM2/3 长度/方向/地址；PREOP 与运行态地址规则不同；剩余 SM Activation 读取不能漏 |
| `Recheck()` / `CanRecheck()` | 状态决策 + AL 执行 | 调用侧 INIT/pending/error 门控；不同当前态的退态动作；不能只保留函数内逻辑而漏调用侧条件 |
| `CheckErrors()` | 采集同步健康事实 → 状态决策 | 过程看门狗、输出是否运行、首帧标志复位、DC 同步序列错误分别处理 |
| `RequestLocalState()` | 状态决策 | 本地退态也要停输出并发布状态/错误，保留主站可观察性 |
| `Publish()` | AL 状态发布叶子 | 先写 0x0134，再写完整 0x0130；错误位、Device ID、RUN/ERR LED 和 0x0138 override 全保留 |
| `SetALEventMask()` / `ResetALEventMask()` | ESC 事件操作 | 位运算语义与访问宽度保持，不能把 retain-mask 当 clear-mask |

参数命名改为 `channel_count` 一类明确数量的形式，前提是所有调用点同时核对。当前 2/4 为排他上界，不是最后一个通道索引。

## 5. 事件和同步的严格对应

本阶段先保留当前分发路径：`OnPdi()` 调用完整 `HandleAlEvents()`。当前注释称部分流程在线程上下文，但真实代码在 ISR 也执行。不能仅按注释搬迁，否则可能留下持续置位的事件造成中断占满。

| 当前入口/逻辑 | 目标归属 | 顺序和分支约束 |
| --- | --- | --- |
| Device `HandleAlEvents()` AL Control | 事件入口 → AL 会话 | 32 位读取 0x0120 确认；处理后从同一快照清 SM_CHANGE，避免重复检查 |
| SM_CHANGE | 同上 | 仅 `CanRecheck()` 成立才重检；0x0010 是事件位，不是 AL 错误码 |
| EEPROM_COMMAND | SII 会话 | 保留仿真模式门控及命令确认，不是简单清日志 |
| SM2/SM3 / SM0/SM1 | PDO / 邮箱会话 | 保留当前快照内分发顺序、区域确认及所有权转移 |
| `HandlePdiEvents()` SM2 | PDO 会话 | 更新计数/间隔→读实际 SM 地址→首帧通知→OP 才交付业务；非 OP 仍确认区域；按输入同步类型决定是否提交 SM3 |
| `HandlePdiEvents()` SM3 | PDO 会话 | 统计和确认主站读完输入，不能把 SM3 计数解释为业务 Tx 次数 |
| `OnSync0()` | PDO 会话内同步调度 | OnSync0 锁存结果 + input_running 才提交，使用实际 SM3 地址 |
| `OnSync1()` | 同上 | 复位 Sync1 计数；仅 Sync1 锁存、输入存在且运行时提交 |
| `OnTick1ms()` | 时间入口 | AL 倒计时、DC watchdog、时间戳推进、SII 延迟计时均保留；慢持久化上下文调整单列 |
| `Poll()` | Device | 邮箱 Service→AL 事件→转换超时→错误检查；诊断观察不替代协议处理 |

`EcatSync` 的方法逐组迁移到 PDO 会话的同步子对象：

| 当前方法 | 必须对应的内部逻辑 |
| --- | --- |
| `BindParameters()` / `ResetParameters()` | 去除成员借用；初始化全部 0x1C32/33 参数、保留项、支持位、计数、DC 时间及用户选择标志 |
| `PrepareSm()` | 读 watchdog divider/time；DC 激活检查；Sync0 周期边界；显式用户同步类型验证；按收发方向推导默认类型 |
| `StartSm()` | 清 watchdog/序列计数；计算 Sync0/Sync1 等待窗、SM/Sync0 比率、输入锁存点，保留整除时的额外计数分支 |
| `StopSm()` | 清锁存、运行、序列及计数；不能只关一个 active 标志 |
| `Tick()` | DC 未启用早返；看门狗饱和计数、双同步超时、错误计数上限与序列判断 |
| `UpdateTimestamp()` | DC64 直接读取；DC32 溢出扩展和上次低字保存；不拿系统 uptime 代替 DC 时间 |
| `OnProcessOutput()` | SM 运行标志、DC 比率复位、missed 递减和输入/输出错误统计同步 |
| `OnSync0()` / `OnSync1()` | watchdog 复位、锁存计数、missed 增量及上限、输入提交时机 |
| `UpdateErrorStatus()` | 将超周期和 SM missed 转成标准对象同步错误 |
| `DeriveSyncType()` / `ValidateSyncType()` | FreeRun、SM、SM2、DC0、DC1 及不支持分支分别保留 |
| hpp 中运行状态/锁存/时间戳 getter | 调度条件也是协议逻辑；不能只迁移 cpp 而丢失 inline 条件 |

若后续把 AL/邮箱从 ISR 延后到线程，必须同时设计事件采样、确认时机、屏蔽/重开、中断丢失防护、队列满处理和状态原子性，并独立验证；不混在这次类关系调整中。

## 6. 邮箱：父对象调度，服务返回应答

目标调用链：邮箱会话取一帧 → 判断协议/CoE 服务 → 调用 SDO 或 Info → 获得“应答就绪 / 无应答 / 协议错误”结果 → 同一邮箱会话提交。服务不调用 `ReplySink`，Device 不再实现 `DispatchMailbox()` / `SubmitReply()` 两个内部环路。

对象读写不由 SDO 保存 Dictionary 引用：SDO 解析请求后返回明确的对象操作需求；邮箱会话向下执行对象访问，把返回的数据/中止码交回 SDO 编码。该过程同步完成，SDO 只保存自己的分段数据和会话状态。Info 的描述查询采用同样的向下调度。不能用一组函数指针把 Dictionary 重新注入服务。

### 6.1 传输和帧寿命

| 当前方法组 | 目标归属 / 保留内容 |
| --- | --- |
| Mailbox `Start()` / `Stop()` | 传输层；SM0/1 地址、长度、重叠校验；启停；关闭时池/队列/read/repeat/store 全部回收、ACK 复位 |
| `Acquire()` / `Release()` / `IsHeld()` / `IsQueued()` | 传输层；只有池拥有内存；所有队列及正在读、重复发送、暂存中的帧都属于持有状态 |
| `Receive()` | 传输层；最小/最大长度、SM 满状态、确认丢弃、池耗尽、重复 counter、稳定槽位入队 |
| `Service()` | 拆为传输推进和会话服务调度；错误应答、发送完成、Repeat 电平变化、队列推进各有对应，不隐式丢帧 |
| `Submit()` / `Transmit()` | 传输层；counter 1..7、直接发送和排队；发送尾部确认；直接发送也必须登记 read_frame |
| `OnSendMailboxRead()` | 传输层；read→repeat、旧 repeat 释放、store/发送队列推进 |
| `OnRepeatRequest()` | 传输层；Repeat 请求两个电平、读邮箱占用时暂存、禁用再启用通道、ACK 更新、重发失败保留帧 |
| `Enqueue()` / `Dequeue()` / `ClearQueue()` | 传输层；容量、环形索引及失败返回完整保留；不得依赖调用者“应该不会满” |
| CoE `Bind()` / `Dispatch()` / `Service()` | Bind 删除；服务选择归邮箱会话；保留不支持服务和非法头不同返回 |
| CoE `ContinueIfInfoPending()` | 后续分片调度归邮箱会话；必须有真实调用点和可用帧才能继续，不能仅保留一个未使用函数 |

帧状态至少明确区分：Free、Received、Processing、SendQueued、InFlight、RepeatSaved、Deferred。允许协议需要的别名时必须明确唯一释放者；不能把“已返回”当成可释放，不能保存局部 `MailboxFrame` 的地址。

### 6.2 SDO / Info 全部路径

| 当前实现 | 迁移后必须保留 |
| --- | --- |
| SDO `Handle()` | 报头/总长检查、忙状态、命令路由、分段方向匹配、错误应答 |
| `HandleInitiate()` | 对象不存在、CA 仅 sub0/1、子索引范围、长度计算 |
| `BuildUpload()` | expedited、normal、segmented 三路；容量不足；首次段元数据和 toggle 初值 |
| `BuildDownload()` | expedited 长度、普通总长与 inline 长度、首段完整性、超容量、单帧提交和分段暂存 |
| `HandleDownloadSegment()` | toggle、末段、有效字节、总长/容量边界；最后一段才写对象；所有 Abort 路径 |
| `HandleUploadSegment()` | 每段大小、恰好满段时是否还有尾段、少于 7 字节填充、结束状态清理及发送失败 |
| `BuildAbort()` / `Reply()` / `Abort()` | 保留线上 abort 编码；Reply 改为返回应答描述；Abort 清会话，提交失败不得伪装成功 |
| Info `Reset()` / `Handle()` | 分片状态清理、16 位 InfoHead 的 opcode 掩码、各请求最小长度和不支持路径 |
| `HandleList()` / `Continue()` / `HandleListFragment()` | listType 0..5、分类计数、索引顺序、容量、FragmentsLeft、Incomplete 和游标；后续帧推进 |
| `HandleObjectDescription()` | Index/DataType/ObjFlags/名称的线格式和容量 |
| `HandleEntryDescription()` | 子索引检查、Info/DataType/BitLength/Access、名称串定位和边界 |
| `NameLength()` / `SkipNames()` 等内部 helper | 也是迁移范围，必须按对象名串真实长度校验，而不是仅保留函数名 |

## 7. 类型化 PDO 和对象访问

### 7.1 trd 声明业务类型，核心处理字节

模板限制在业务门面和 Profile 生成器，AL/SDO/硬件核心不因业务类型整体模板化。门面使用 `memcpy` 或显式字段编解码，禁止将未对齐 ESC 字节指针强转成业务结构体。

Profile 是唯一映射来源，同时生成 PDO 字节布局、0x1600/1A00、0x1C12/13、0x6000/7010 描述、分段容量上限。不能只把业务结构挪到 trd，却继续在 core 编译固定的 counter[64]。

`sizeof(T)` 仅适用于明确无填充、线格式等于内存格式的简单布局；一般结构使用字段描述，明确索引/子索引/位长/偏移/大小端。不能用“可平凡复制”证明不存在 padding。允许 Rx/Tx 长度不同及单方向为零，不把当前对称 UDINT 示例当成所有业务约束。

当前基线是每方向 **64 UDINT、256 字节**，不是历史日志中的 8 UDINT。映射表 CA 需要 **2 + 64 × 4 = 258 字节**；邮箱仍为 128 字节，通过 SDO 分段传输，不能扩大邮箱冒充修复。

## 9. 已排错代码的回归红线

以下要求是实施检查清单，不允许以“后面再对齐”交付：

1. expedited SDO 总长 16 字节，邮箱 payload 长 10 字节；不要再次写成 12 字节总长。
2. 逻辑映射表/分配表的 CA 真正返回数据；当前映射读取必须支持 258 字节分段缓冲。
3. 内存不足 `0x05040005` 与 toggle 不变 `0x05030000` 分开，不能再次混用。
4. 0x1C00 子项使用真实字节偏移，主站读出 SM 类型 1/2/3/4；不可按 uint16_t 步进。
5. 0x1C12/13、0x1600/1A00、SM2/3 和实际业务长度来自同一 Profile；先映射再验证 SM。
6. SM Activation 是 `0x0806 + 8*n`，不是长度字段 `+2`；平台若对齐读，用覆盖该字节的正确宽度。
7. 读取 SM Activation 的剩余通道循环、AL Control 的 32 位确认、非 OP 的 PDO 区域确认均不能省略。
8. 同一事件快照已经处理 AL Control 后，不再重复处理 SM_CHANGE。
9. OP 首帧等待、超时、错误 ACK、退态后输出门控保持；恢复收到 SM2 不意味着自动回 OP。
10. 软件态 0x04 与线上错误态 0x0014 区分；0x001B 是过程看门狗，主站必须能读到实际 AL Status/Code。
11. 既往约 100 ms 无过程输出触发退态是已观测现象，29 秒/58 秒历史间隔不证明从站计数溢出，也未单凭从站日志定位原始断流方。
12. 直接发送邮箱帧仍归池管理，登记 in-flight；repeat/store/read 指针不可过早释放。
13. Reset/Disable 清 SDO 和 Info 会话；Reset 完成要重新开事件，Disable 不重新开。
14. 不把 ISR 完整分发擅自缩成只有 PDO；不得出现未确认事件持续触发而线程饿死。
15. 首次故障永久保留到显式清除，停收后不继续每秒刷相同错误，正常业务日志不能挤掉故障现场。
16. 当前 256 字节双向实例与历史 32 字节实例均作为 Profile 样例；不能强制所有 Rx/Tx 对称。
17. 标准对象、LED、Device ID、不支持的 BOOT、同步错误等非主路径仍属于实现范围。
18. 保留 `LICENSE-BECKHOFF.md` 及相关来源/许可说明，重组不抹掉原始来源。

## 10. 现存问题与结构迁移分开处理

“严格对齐”指现有行为全部有去向、协议条件逐项核验，不表示复制已确认错误。下列项建立独立问题单，修复需要单独差异、依据及验证，不暗藏在类移动中。

| 项目 | 当前证据 / 风险 | 修改方向 |
| --- | --- | --- |
| D1 权限位移错误 | `model/ecat_dictionary.cpp:532` 使用 `1U << state`；AlState 为 1/2/4/8，而权限读位为 1/2/4，当前又与 `mask << 1` 比较。SAFEOP/OP 无法按预期命中 | 直接把对齐后的权限掩码与 AL 状态值比较，或显式 switch；读写×三状态逐项真值表，禁止再把状态值当位号 |
| D2 稀疏 PHY 端口 | `ethercat.cpp` 按真实 port 存 phys，但 Poll 只遍历 `port < phy_count_` | 遍历固定端口范围并跳空，或显式端口配置表；保留真实 port 到 MDIO/链路的映射 |
| D3 生命周期窗口 | Device Init 在 ready 前 StartEvents；外层此后才初始化 PHY；trd 在 Init 返回后才装业务回调；PHY 失败没有统一回收 | 按第 3 节拆 Prepare/Start 的内部阶段，统一逆序失败清理 |
| D4 字典 CA 一致性 | Read/Write 对无权限/保留项的跳过方式、线长计算与各项状态检查不同；Write 逐项修改可能部分成功 | 逐对象列线偏移，确定保留位占位和权限错误语义；候选值验证完再提交，不能笼统 memcpy |
| D5 Info 扩展边界 | 固定 indices[32]、槽表未天然按索引排序；后续 Continue 调度未形成完整调用链；名称最大长度还需预留终止字节 | 明确按 Profile 数量配置、有序游标、帧资源和续片推进；核对 SSC 的响应/错误格式与长度 |

| D7 状态/资源收尾 | Recheck 的 OP 失败路径调用 LeaveSafeOp 后标记 SAFEOP；各目标失败清理方式不同；BackToInit 存在 guard 后无条件 sync 解引用 | 按转换表核验状态和资源不变量，补齐失败清理；去依赖后不能简单删除所有异常分支 |
| D8 SII 上下文/单位 | Tick 可走 StoreSii；HPM timer 是中断上下文；reload 地址与 kSiiSizeBytes 比较需要核对单位 | Tick 只计时并置请求，线程执行持久化；字地址/字节数统一检查；明确修改相对基线的上下文差异 |
| D9 邮箱极端路径 | repeat 无历史帧时 ACK、重发失败入队、队列满和别名释放路径需要逐支核验 | 建帧状态转移表及失败返回传播；不以正常 SDO 跑通证明重发可靠 |
| D10 硬件永久等待 | Enable/Disable SM 有无界等待 | 依据硬件契约另行决定超时和故障上报；纯重构阶段不得私自改变返回类型并吞失败 |
